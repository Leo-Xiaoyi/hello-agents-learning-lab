# 第 1–3 章｜智能体怎样运行

我对智能体、大语言模型和固定工作流的基本理解。来源：[Hello-Agents](https://github.com/datawhalechina/hello-agents) 第 1–3 章。

## 第 1 章：Agent 是怎样工作的

Agent 接到任务后，可以多次调用模型和工具。模型根据当前信息判断下一步；程序保存状态、执行工具，并决定何时结束。这个过程比单次问答多了一个持续运行的循环。

```text
用户任务
  → 整理当前状态与可用工具
  → 模型提出下一步：回答 / 调用工具 / 继续处理
  → 程序执行并取得结果
  → 把结果放回当前状态
  → 继续或结束
```

关键在于这个循环：一次模型调用可能只完成一步。工具结果进入下一轮后，Agent 才能根据新信息调整判断。

### 模型、工具、状态各负责什么

- 模型：理解目标，选择下一步，或生成回答。模型提出工具调用后，仍要由程序执行。
- 工具：执行搜索、计算、读取文件等动作，把结果返回给 Agent。工具结果也需要判断和核对。
- 状态：保存任务进度、已采取的动作、工具结果和必要的历史，供下一次模型调用使用。
- 控制流程：检查动作是否合法，处理错误，并设置步数上限和结束条件。

我现在会用四个问题检查一个 Agent 的设计：模型能看到什么、能做什么、动作结果怎样回来、什么时候结束或交给人。

### 固定流程和 Agent 怎样区分

固定工作流的步骤和分支主要由开发者预先设定。Agent 则允许模型根据当前信息决定部分后续动作。两者可以放在同一个系统里：外层用固定流程管住边界，某个需要探索的步骤交给 Agent 判断。

如果任务路径稳定，就把步骤写明确；如果下一步依赖随时出现的新信息，再给模型留出选择空间。自主选择越多，越需要记录状态、限制工具权限并规定何时停止。

## 第 2 章：从规则式智能体到大模型智能体

第 2 章回顾智能体的发展。早期系统依赖预先写好的规则，能处理设计者想到的情况，遇到规则外的问题就容易卡住。大语言模型让智能体可以根据文字描述和当前信息，更灵活地判断下一步。

模型能灵活判断下一步，但外部动作仍由工具执行。状态、权限和错误处理也还在程序里。大模型改变的是决策方式，没有替程序承担全部职责。

## 第 3 章：模型每次究竟看到了什么

对我理解 Agent 最有用的一点是：模型根据这一次请求提供的内容生成回复。它不会因为上次聊过，就自动在新请求里保留那段历史；也不会自己读取本地文件。应用要把相关历史、文件片段或工具结果整理好，再送入这次调用。

模型可以提出计划、回答问题，也可能给出错误或缺乏依据的内容。输入里放什么信息、输出有没有依据，都需要应用来处理。我把“能生成回答”和“有可靠依据”分开看。

## 我整理的一轮问答流程

假设任务需要查资料后再回答，我把流程记成这样：

1. 接收任务，明确目标、要求和可用工具。
2. 从历史、记忆、文档和笔记里找本轮需要的信息，整理后交给模型。
3. 模型决定回答、调用工具，或继续处理某个步骤。
4. 程序检查并执行动作，把结果放回当前状态。
5. 模型根据新结果继续或结束；程序处理异常和步数上限。
6. 本轮结束后，按需保存历史，以及值得长期保留的信息。

具体任务不一定用到记忆、检索或所有工具。我主要用这条流程区分取资料、决定动作和执行动作这几件事。
